# SIMULATION_SPEC.md — Simulation Specification

## 1. Simulation Time Model

The simulation operates on discrete logical ticks decoupled from framerate.

### Tick Duration
- **1 Core Simulation Tick = 10 Simulated Minutes**
- **6 Ticks = 1 Simulated Hour**
- **144 Ticks = 1 Simulated Day (24 hours)**
- **52,560 Ticks = 1 Simulated Year (365 days)**

### Realtime Pacing Target
- **Target Pace (1× Speed)**: Approximately 45 real-world minutes per 1 simulated year.
- **Tick Rate at 1×**: `52,560 ticks / (45 * 60 seconds) ≈ 19.47 ticks/second` (~51.3 ms per tick budget in realtime).
- **Speed Multipliers**:
  - `PAUSE`: 0 ticks/sec
  - `1×`: ~19.5 ticks/sec (45 mins/yr)
  - `2×`: ~38.9 ticks/sec (22.5 mins/yr)
  - `4×`: ~77.9 ticks/sec (11.25 mins/yr)
  - `8×`: ~155.7 ticks/sec (5.6 mins/yr)
  - `HEADLESS / BENCHMARK`: As fast as compute permits (target > 5,000 ticks/sec for fast CI/test execution).

## 2. Determinism Specification

Determinism is an absolute invariant across the entire codebase.

### Guarantee
Given:
1. Identical initial `WorldState`
2. Identical initial PRNG seed
3. Identical sequence of player inputs / external events at identical tick indices
4. Identical total tick count

The resulting `WorldState` checksum must be bit-for-bit identical across all runs, platforms, and architectures.

### Determinism Rules
- **No Engine Random Calls**: Never call `randi()`, `randf()`, `randf_range()`, or `Array.shuffle()` directly. All randomness must use `world_state.rng` (`SeededRandom`).
- **Stable Iteration Order**: Never iterate over Godot `Dictionary.keys()` or associative arrays when modifying simulation state unless keys are explicitly sorted or order-independent.
- **Integer IDs**: Entity references must use monotonic integer IDs generated by `EntityRegistry`.
- **Pure Functional Transformations**: Systems must process deterministic inputs and apply deterministic state mutations.

## 3. Simulation Level of Detail (LOD)

Every citizen, machine, and room remains an actual persistent entity in memory. However, computational fidelity scales according to observational focus.

```
                    ┌─────────────────────────┐
                    │      ACTIVE LOD         │
                    │ (Directly observed /    │
                    │  critical incidents)    │
                    └───────────┬─────────────┘
                                │
                    ┌───────────┴─────────────┐
                    │     SCHEDULED LOD       │
                    │ (Normal residents:      │
                    │  daily routines/travel) │
                    └───────────┬─────────────┘
                                │
                    ┌───────────┴─────────────┐
                    │     ABSTRACTED LOD      │
                    │ (Sleeping / off-shift / │
                    │  remote components)     │
                    └─────────────────────────┘
```

### Golden Rule of LOD
> **"LOD may reduce computational cost but must never invent or remove simulation truth."**

- **Active LOD**: Physical-level zone interactions, precise path node transitions, fine-grained telemetry.
- **Scheduled LOD**: Discrete activity updates at schedule boundaries, estimated transit times between sectors without path node polling.
- **Abstracted LOD**: State advancement via mathematical formulas or scheduled wake-up ticks (e.g. sleep recovery computed in bulk at wake tick).

## 4. Population & Scale Targets

The baseline mature silo simulation contains:
- **Baseline Lore Population**: ~1,200 persistent residents
- **Scale Benchmarks**:
  - Stage 1: 100 residents
  - Stage 2: 250 residents
  - Stage 3: 500 residents
  - Stage 4: 1,200 residents (Mature target)
  - Stress Target: 3,000+ residents

All systems must run comfortably within the headless tick performance budget at 1,200 entities.

---

## 5. Technology Level

The technology level is grounded, realistic, and modern / near-modern industrial:
- **Computing & Networks**: Ethernet, optical fibre, managed switches, servers, RAID storage, relational/time-series databases, PLCs, RTUs, SCADA networks.
- **Security & Access**: RFID/magnetic badges, electronic strike locks, CCTV coax/IP streams, turnstiles, clearance matrices.
- **Industrial Infrastructure**: 3-phase AC induction motors, centrifugal pumps, pneumatic actuators, metal lathes, milling machines, induction furnaces, ventilation dampers, air scrubbers, RO water filtration.
- **No Fantasy/Sci-Fi Tropes**: No teleporters, magical energy shields, or hand-waved infinite power crystals unless grounded physical equivalents exist.
